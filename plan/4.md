### 一、 核心疑问解答与性能分析

#### 1. 扫描可执行文件（`/usr/bin` 等）会不会严重拖慢速度？
**答案：完全不会，只要遵循缓存机制。**
* **数量与 IO 成本**：Linux 下所有 PATH 目录下的二进制文件加起来通常在 **2,000 ~ 5,000 个**。在 Rust 中做简单的目录扁平遍历（只读文件名，不需要像图标那样深度递归），耗时仅需 **3 ~ 8ms**。
* **冷热启动机制**：
  * **日常唤醒（热启动）**：二进制文件连同 desktop 一起序列化保存在 `stools-apps-v1.bin` 缓存中，启动时 `bincode` 反序列化 5,000 条纯字符串数据**耗时 < 1.5ms**。
  * **异步更新**：后台线程每隔一段时间或启动时在后台静默重扫并覆写缓存，完全不阻塞前台 UI。

#### 2. 搜索历史应该放 SQLite 还是 JSON？
**答案：坚决推荐 `~/.local/share/stools/history.json`（轻量 JSON 文件）。**
* **理由**：
  * 启动器的历史记录通常只需保留最近执行过的 50 ~ 200 条（记录 `id`, `last_used_timestamp`, `count`）。
  * 引入 SQLite 会增加 2~4MB 的二进制体积和 C 依赖编译时间，而读取一个几十 KB 的 `history.json` 耗时只有 **0.1ms**。
  * JSON 格式简单透明，用户也方便查看或直接清空。

```rust
use std::collections::HashMap;
use std::fs;
use std::path::PathBuf;
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize, Default, Clone)]
pub struct HistoryRecord {
    pub last_used: u64,
    pub count: u32,
}

pub struct HistoryManager {
    file_path: PathBuf,
    pub records: HashMap<String, HistoryRecord>,
}

impl HistoryManager {
    pub fn load() -> Self {
        let dir = dirs::data_local_dir()
            .unwrap_or_else(|| PathBuf::from("."))
            .join("stools");
        let _ = fs::create_dir_all(&dir);
        let file_path = dir.join("history.json");

        let records = fs::read_to_string(&file_path)
            .ok()
            .and_then(|s| serde_json::from_str(&s).ok())
            .unwrap_or_default();

        Self { file_path, records }
    }

    pub fn record_hit(&mut self, id: &str) {
        let now = std::time::SystemTime::now()
            .duration_since(std::time::UNIX_EPOCH)
            .unwrap()
            .as_secs();

        let entry = self.records.entry(id.to_string()).or_default();
        entry.last_used = now;
        entry.count += 1;

        if let Ok(json) = serde_json::to_string_pretty(&self.records) {
            let _ = fs::write(&self.file_path, json);
        }
    }
}
```

#### 1. 修复 3 层优先级排序 (`src/core/matcher.rs`)

建立严格的三层排序规则：
* **Tier 1（最高）**：历史记录（按最近使用时间倒序）
* **Tier 2（次高）**：`.desktop` 桌面应用
* **Tier 3（最低）**：CLI 可执行文件

```rust
// 替换 src/core/matcher.rs 中的 rank 函数
pub fn rank(
    items: &[AppEntry],
    query: &str,
    matcher: &mut Matcher,
    scratch: &mut MatcherScratch,
    history: Option<&std::collections::HashMap<String, HistoryRecord>>,
) -> Vec<usize> {
    let query = query.trim();

    // --- 1. 空搜索词：严格按照 [历史使用] -> [Desktop 软件] -> [Binary 命令] 排序 ---
    if query.is_empty() {
        let mut idxs: Vec<usize> = (0..items.len()).collect();
        idxs.sort_by(|&a, &b| {
            let entry_a = &items[a];
            let entry_b = &items[b];

            let hist_a = history.and_then(|h| h.get(&entry_a.id)).map_or(0, |r| r.last_used);
            let hist_b = history.and_then(|h| h.get(&entry_b.id)).map_or(0, |r| r.last_used);

            // 1. 历史记录优先（时间最新排在最前）
            match (hist_a > 0, hist_b > 0) {
                (true, true) => return hist_b.cmp(&hist_a),
                (true, false) => return std::cmp::Ordering::Less,
                (false, true) => return std::cmp::Ordering::Greater,
                (false, false) => {}
            }

            // 2. Desktop 桌面应用 优先于 Binary 可执行文件
            match (&entry_a.kind, &entry_b.kind) {
                (super::model::EntryKind::Desktop, super::model::EntryKind::Binary) => {
                    return std::cmp::Ordering::Less;
                }
                (super::model::EntryKind::Binary, super::model::EntryKind::Desktop) => {
                    return std::cmp::Ordering::Greater;
                }
                _ => {}
            }

            // 3. 保持原顺序
            a.cmp(&b)
        });
        return idxs;
    }

    // --- 2. 有搜索词：模糊打分 + Desktop 基础权重 + 历史使用加成 ---
    let mut results: Vec<(usize, u32)> = Vec::with_capacity(items.len());
    for (i, entry) in items.iter().enumerate() {
        if let Some(base_score) = score(
            entry,
            matcher,
            query,
            &mut scratch.name_buf,
            &mut scratch.abbr_buf,
            &mut scratch.full_buf,
            &mut scratch.query_buf,
        ) {
            let mut total_score = base_score as u32;

            // Desktop 应用基础加分（确保同样匹配度下 GUI 软件优先）
            if entry.kind == super::model::EntryKind::Desktop {
                total_score += 1000;
            }

            // 历史使用频率加权
            if let Some(hist) = history {
                if let Some(h) = hist.get(&entry.id) {
                    total_score += (h.count.min(20) * 50) as u32;
                }
            }

            results.push((i, total_score));
        }
    }

    results.sort_by(|a, b| b.1.cmp(&a.1));
    results.into_iter().map(|(i, _)| i).collect()
}
```

```rust
fn scan_binaries(dirs: &[PathBuf]) -> Vec<AppEntry> {
    let mut entries = Vec::new();

    for dir in dirs {
        let Ok(rd) = fs::read_dir(dir) else { continue };
        for entry in rd.flatten() {
            let path = entry.path();
            let Ok(meta) = entry.metadata() else { continue };
            if !meta.is_file() || meta.permissions().mode() & 0o111 == 0 {
                continue;
            }
            let Some(name) = path.file_name().and_then(|s| s.to_str()) else {
                continue;
            };
            if name.starts_with('.') {
                continue;
            }

            let (pinyin_full, pinyin_abbr) = matcher::pinyin_fields(name);
            let id = format!("bin:{}", path.to_string_lossy());

            entries.push(AppEntry {
                id,
                name: name.to_string(),
                exec: path.to_string_lossy().into_owned(),
                icon_path: None,
                hidden: false,
                pinyin_full,
                pinyin_abbr,
                kind: EntryKind::Binary,
                subtitle: None, // 先置空，后续统一做冲突检测
            });
        }
    }
    entries
}

fn scan_apps(binary_dirs: &[PathBuf]) -> Vec<AppEntry> {
    let icon_map = build_icon_map();
    let mut entries = Vec::new();
    let mut seen_ids: HashSet<String> = HashSet::new();

    // 1. 扫描所有 .desktop 文件
    for dir in desktop_dirs() {
        let Ok(rd) = fs::read_dir(&dir) else { continue };
        let mut files: Vec<_> = rd.flatten().map(|e| e.path()).collect();
        files.sort();
        for path in files {
            if path.extension().and_then(|e| e.to_str()) != Some("desktop") {
                continue;
            }
            let id = path
                .file_name()
                .and_then(|s| s.to_str())
                .unwrap_or_default()
                .to_string();
            if !seen_ids.insert(id.clone()) {
                continue;
            }
            if let Some(entry) = parse_desktop(&path, &id, &icon_map) {
                entries.push(entry);
            }
        }
    }

    // 2. 扫描所有二进制可执行文件
    let binaries = scan_binaries(binary_dirs);
    entries.extend(binaries);

    // 3. 🎯 统计所有项目名称的出现频次（区分大小写不敏感冲突）
    let mut name_counts: HashMap<String, usize> = HashMap::new();
    for e in &entries {
        *name_counts.entry(e.name.to_lowercase()).or_insert(0) += 1;
    }

    // 4. 🎯 只有重名的项目才标记副标题路径，唯一名称的不显示路径！
    for e in &mut entries {
        if name_counts.get(&e.name.to_lowercase()).copied().unwrap_or(0) > 1 {
            e.subtitle = Some(path_utils::prettify_path(Path::new(&e.exec)));
        } else {
            e.subtitle = None;
        }
    }

    entries
```

### 一、 5 个问题的根因分析

1. **为什么每一项又变成居中了？**
   * **原因**：PI 在列表项的 `HorizontalLayout` 里面又加回了 `alignment: center;`。当项目没有副标题时，单行文本被强行居中在整个窗口宽度里。

2. **为什么灰色路径偏上、没和名称垂直对齐？**
   * **原因**：副标题的 `Text` 标签没有设置 `height: 100%`，导致它只占了字体的高度（约 12px）并紧贴容器顶部 $Y=0$。
   * **修复**：给副标题 `Text` 显式设置 `height: 100%; vertical-alignment: center;`，与左侧名称共用同一条中轴线。

3. **为什么跑马灯滚动到虚无/输入 `qute` 后直接变空白了？**
   * **原因**：PI 硬编码了 `subtitle_scroll_x: 900px`。当一个路径只有 260px 时，向左平移 900px 会直接把文字**丢出裁剪框外几百像素的虚无区域**，看起来就像变空白了一样。
   * **修复**：采用**精准溢出计算**——通过 `self.preferred-width - container.width` 动态计算超出裁剪区域的真实像素数，文字刚好滚到末尾停住，绝不会跑丢。

4. **为什么光标离开后没有瞬间复位？**
   * **原因**：PI 设置的动画时间是固定双向 10 秒。光标移开时，它还在花 10 秒慢吞吞地往回滚。
   * **修复**：在 Slint 中使用条件动画时长：`duration: (root.selected_index == index) ? 3s : 0ms;`。**选中时用 3 秒平滑滚完，光标一离开瞬间（0ms）回到起始位置**。

5. **小建议：Desktop 应用不需要显示 `.desktop` 冗余字样**：
   * 在 `scan_apps` 中，重名时只有二进制才需要标记路径 `/usr/bin/qutebrowser`，GUI 应用已有彩色图标，不标记副标题更干净。

### 一、 问题根因分析

#### 1. 为什么指定 `/home/captain` 后，复制进去的 `.desktop` 没有出现？
有以下两个原因共同导致：
* **原因 A（致命）**：在目前的代码中，命令行传入的参数 `cli_dirs` 只被传递给了 `scan_binaries`（可执行文件扫描器）。
  * `scan_binaries` 会检查文件的执行权限（`mode & 0o111 != 0`）。而通常复制出来的 `.desktop` 文件权限是 `0644`（不可执行），因此被直接过滤了；而且即使有执行权限，它也不会按照 `.desktop` 格式去解析。
* **原因 B（缓存拦截）**：`load_apps` 发现本地已经有 `stools-apps-v3.bin` 缓存时，**会先直接返回旧缓存**，后台异步刷新。所以第 1 次带参数运行时，前台读到的依然是未包含新目录的旧数据。

#### 2. 为什么当前没有看到跑马灯？
* 因为目前截图中的唯一副标题是 `/usr/bin/qutebrowser`，它的字符长度大约只有 140px，而你设定的副标题最大容器宽度是 `210px`。
* **没有超出 210px（`overflow_dist == 0`）**，系统判定文字完全看得全，所以按设计**静态停靠在右侧**，不需要跑马灯。
* 一旦路径很深、字符超过 210px，就会立即触发平滑滚动的跑马灯。

```rust
// 替换 src/platform/linux.rs 中的 desktop_dirs 与 scan_apps

fn desktop_dirs(custom_dirs: &[PathBuf]) -> Vec<PathBuf> {
    let mut dirs = Vec::new();
    
    // 优先加入用户指定的自定义目录
    for cd in custom_dirs {
        dirs.push(cd.clone());
    }

    let home = std::env::var("HOME").unwrap_or_default();
    if !home.is_empty() {
        dirs.push(PathBuf::from(&home).join(".local/share/applications"));
        dirs.push(PathBuf::from(&home).join(".local/share/flatpak/exports/share/applications"));
        // 也把家目录和桌面包含进常见检查中
        dirs.push(PathBuf::from(&home).join("Desktop"));
    }
    let data_home = std::env::var("XDG_DATA_HOME").unwrap_or_default();
    if !data_home.is_empty() {
        dirs.push(PathBuf::from(data_home).join("applications"));
    }
    dirs.push(PathBuf::from("/usr/local/share/applications"));
    dirs.push(PathBuf::from("/usr/share/applications"));
    if let Ok(data_dirs) = std::env::var("XDG_DATA_DIRS") {
        for d in data_dirs.split(':') {
            if !d.is_empty() {
                dirs.push(PathBuf::from(d).join("applications"));
            }
        }
    }
    let mut seen = HashSet::new();
    dirs.retain(|d| seen.insert(d.clone()));
    dirs
}

fn scan_apps(custom_dirs: &[PathBuf]) -> Vec<AppEntry> {
    let icon_map = build_icon_map();
    let mut entries = Vec::new();
    let mut seen_ids: HashSet<String> = HashSet::new();

    // 1. 扫描所有 .desktop 文件（包含 custom_dirs）
    for dir in desktop_dirs(custom_dirs) {
        let Ok(rd) = fs::read_dir(&dir) else { continue };
        let mut files: Vec<_> = rd.flatten().map(|e| e.path()).collect();
        files.sort();
        for path in files {
            if path.extension().and_then(|e| e.to_str()) != Some("desktop") {
                continue;
            }
            let id = path
                .file_name()
                .and_then(|s| s.to_str())
                .unwrap_or_default()
                .to_string();
            // 如果来自不同目录的同一 .desktop（比如 ~/ 和 /usr/share/），用绝对路径作 ID 避免去重丢失
            let unique_id = format!("{}:{}", dir.display(), id);
            if !seen_ids.insert(unique_id) {
                continue;
            }
            if let Some(entry) = parse_desktop(&path, &id, &icon_map) {
                entries.push(entry);
            }
        }
    }

    // 2. 扫描所有二进制可执行文件
    let binaries = scan_binaries(custom_dirs);
    entries.extend(binaries);

    // 3. 重名检测（同名项目触发路径副标题）
    let mut name_counts: HashMap<String, usize> = HashMap::new();
    for e in &entries {
        *name_counts.entry(e.name.to_lowercase()).or_insert(0) += 1;
    }

    for e in &mut entries {
        if name_counts.get(&e.name.to_lowercase()).copied().unwrap_or(0) > 1 {
            // 如果同时存在多个重名，无论是桌面应用还是二进制，都显示美化路径以便区分
            e.subtitle = Some(path_utils::prettify_path(Path::new(&e.exec)));
        } else {
            e.subtitle = None;
        }
    }

    entries
}
```

### 一、 问题根因分析

* **原因**：在上一版的 `linux.rs` 中，PI 写了一行硬编码：

#### 2. 为什么跑马灯跑完直接从头开始，而不是尾部空一格无缝循环接上？
* **原因**：单一的 `Text` 标签在动画从 `-Xpx` 循环回到 `0px` 时，只是一次跳变。当文字末尾刚刚滚入视野时，右侧是空的，直到整个动画结束才会突然闪回开头。
* **无缝跑马灯（Dual-Text Seamless Ribbon）原理**：
  * 在裁剪框内放置 **2 个相同的文本**：
    * **主文本 (Text 1)**：从 `0px` 匀速向左移动到 `-(文本宽 + 间距)`；
    * **跟随后缀文本 (Text 2)**：紧紧跟在主文本后面（偏移 `文本宽 + 间距`）。
  * 当主文本向左移出可视区时，后置文本恰好无缝填补到 `0px` 的位置。此时动画重置，**视觉上完全没有跳变，实现真正无缝、无限流转的跑马灯**。

```rust
// 替换 src/platform/linux.rs 中的 parse_desktop 和 scan_apps 中的重名处理部分

fn parse_desktop(
    path: &Path,
    id: &str,
    icon_map: &HashMap<String, PathBuf>,
) -> Option<AppEntry> {
    let content = fs::read_to_string(path).ok()?;
    let mut name = None::<String>;
    let mut exec = None::<String>;
    let mut icon = None::<String>;
    let mut hidden = false;
    let mut no_display = false;
    let mut is_application = false;
    let mut in_desktop = false;
    let mut localized_names: Vec<String> = Vec::new();

    for raw_line in content.lines() {
        let line = raw_line.trim();
        if line.is_empty() || line.starts_with('#') {
            continue;
        }
        if line.starts_with('[') && line.ends_with(']') {
            in_desktop = line == "[Desktop Entry]";
            continue;
        }
        if !in_desktop {
            continue;
        }
        let Some(eq) = line.find('=') else { continue };
        let (key, value) = (line[..eq].trim(), line[eq + 1..].trim());
        match key {
            "Type" => is_application = value == "Application",
            "Name" => name = Some(value.to_string()),
            "Exec" => exec = Some(value.to_string()),
            "Icon" => icon = Some(value.to_string()),
            "Hidden" => hidden = parse_bool(Some(value), false),
            "NoDisplay" => no_display = parse_bool(Some(value), false),
            _ => {
                if let Some(rest) = key.strip_prefix("Name[") {
                    if rest.ends_with(']') {
                        localized_names.push(value.to_string());
                    }
                }
            }
        }
    }

    if !is_application {
        return None;
    }
    let name_str = localized_names.pop().or(name)?;
    let exec_value = exec?;
    let (pinyin_full, pinyin_abbr) = matcher::pinyin_fields(&name_str);

    Some(AppEntry {
        // 🎯 关键：id 保存 .desktop 的真实绝对路径，后续重名时用来提取路径展示
        id: path.to_string_lossy().into_owned(),
        name: name_str,
        exec: exec_value,
        icon_path: icon.and_then(|i| resolve_icon(&i, icon_map)),
        hidden: hidden || no_display,
        pinyin_full,
        pinyin_abbr,
        kind: EntryKind::Desktop,
        subtitle: None,
    })
}
```

**Slint 的 `animate` 动画本质上是“状态变化驱动”（State-Change Triggered）的。**

---

### 一、 为什么搜索出第 1 项超长时不会自动跑起来？

1. 在未输入任何内容时，默认选中的就是第 1 项（`selected_index == 0`）。
2. 当你在输入框中敲入 `qute` 时，Rust 端重新构建了列表，并再次设置 `ui.set_selected_index(0)`。
3. **关键原因**：对于第 1 项（`index == 0`）来说，它的选中状态从始至终都是 `true`（`0 == 0`），**并没有经历从 `false` 到 `true` 的状态跳变**！
4. Slint 认为该组件的目标值一直都是固定值，因此**不会触发属性的过渡动画（`animate x`）**；只有当你按 `↓` 再按 `↑` 触发了 `false -> true` 的状态切换时，动画才被激活。

---

### 二、 修复方案

解决办法非常简单且优雅：在 Rust 端每次重新构建列表（`set_items`）时，**先短暂将 `selected_index` 置为 `-1`，随后立即恢复为 `0`**：

1. `set_selected_index(-1)`：此时所有新渲染的列表项其状态都是 `active: false`，文本绝对固定在初始的 `0px` 处；
2. `set_selected_index(0)`：瞬间激活第 1 项，状态由 `false -> true`，**立即触发第 1 项从 `0px` 开始向左无缝跑马灯**！
